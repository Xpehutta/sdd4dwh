# Proposal: make-load-deterministic

## Why

Загрузка `d_agr_cred` недетерминирована: отбор действующей привязки клиента (`d_agr_cred_cust`) использует текущую дату сервера (`('now'::text)::date`), поэтому повторные прогоны за одну и ту же отчётную дату в разные календарные дни могут давать разные результаты. Это противоречит требованию идемпотентности из спецификации `credit-agreements` и мешает воспроизводимости разбора инцидентов. Параметризация датой отчёта зафиксирована как следующий шаг в дизайне первого изменения — реализуем её.

## What Changes

- В `sql/d_agr_cred_load.sql` оба вхождения `('now'::text)::date` (предикат подзапроса `cst`) заменяются на параметр даты отчёта `:'report_dt'::date`.
- Регламент: дата отчёта передаётся при запуске явно (`psql -v report_dt=YYYY-MM-DD`); запуск без параметра — ошибка; подстановка текущей даты запрещена.
- Спека `credit-agreements`: MODIFIED — «Регламент загрузки и идемпотентность» (детерминированность по `report_dt`); ADDED — «Выбор привязки клиента (subject area)» (правила 1/2/3 на дату отчёта).
- Проверки: в SQL не остаётся `now()` / `current_date`; DQ-набор не меняется.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `credit-agreements`: детерминированность загрузки по дате отчёта; явное требование к выбору привязки клиента.

## Impact

- `sql/d_agr_cred_load.sql` — предикат отбора `d_agr_cred_cust` (два вхождения) + пояснительные комментарии.
- Регламент запуска — добавить передачу параметра `report_dt` (раннер загрузки).
- Состав колонок и остальные правила не меняются; потребители данных не затрагиваются (результаты становятся воспроизводимыми).
