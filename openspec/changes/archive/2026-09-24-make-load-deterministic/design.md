# Design: make-load-deterministic

## Context

Первый change (`add-d-agr-cred-load`) зафиксировал контракт загрузки и явно отметил недетерминированный предикат: в подзапросе `cst` отбор записи `d_agr_cred_cust` выполняется по текущей дате сервера (`('now'::text)::date`). Повторный прогон за ту же отчётную дату в другой календарный день может дать другой результат — нарушение идемпотентности из спеки `credit-agreements`. Изменение делает дату отчёта явным параметром запуска.

## Goals / Non-Goals

**Goals:**

- Детерминированность: результат загрузки зависит только от данных источников и `report_dt`.
- Явный параметр запуска и правило «без параметра — ошибка».
- Статическая проверяемость: в SQL нет `now()` / `current_date`.

**Non-Goals:**

- Прочие кандидаты на улучшение (например, изоляция подзапроса валют) — отдельные изменения.
- Изменение правил классификации `subject_area_type_id` (правила лишь фиксируются спекой).
- Изменения состава колонок и других потоков.

## Decisions

1. **Форма параметра — psql-переменная `:'report_dt'`.** Штатный механизм для запуска `.sql` через `psql` (Greenplum): значение подставляется до отправки на сервер. Альтернативы: обёртка-процедура с аргументом (меняет инфраструктуру запуска — избыточно для одного параметра); фолбэк `COALESCE(:report_dt, current_date)` (возвращает недетерминизм — отклонено).
2. **Оба вхождения заменяются в одном предикате** (`>= start_dt`, `<= end_dt`) — это одно условие «запись, действующая на дату отчёта».
3. **Без параметра — ошибка запуска.** Регламент требует явного `report_dt`; подстановка текущей даты запрещена осознанно — именно её мы убираем.
4. **Откат** — `git revert` коммита применения; регламент возвращается к прежней форме запуска.

## Risks / Trade-offs

- [Раннер загрузки должен начать передавать параметр] → fail-fast лучше тихой подстановки: запуск без `report_dt` падает.
- [Отчётная дата может отличаться от даты фактической загрузки — это целевое поведение] → сверки и мониторинг учитывают `report_dt`.

## Migration Plan

Один коммит: правка предиката + комментарии; обновление регламента (передача `report_dt`). Проверка в песочнице: прогон с `report_dt = T-1` и повторный прогон на следующий день — состояние совпадает.

## Open Questions

- Формат передачи параметра в текущем загрузчике: если запуск не через `psql` — адаптировать под имеющийся инструмент (смысл не меняется).
