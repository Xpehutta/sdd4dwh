# Proposal: add-d-agr-cred-load

## Why

Загрузка DDS-таблицы `s_grnplm_vd_t_bvd_db_dmslcl.d_agr_cred` (кредитные договоры) существует как один большой `INSERT ... SELECT` на 349 строк с тремя потоками `UNION ALL`, но у неё нет зафиксированного контракта: правила даты выдачи, валюты и цессии закодированы в `CASE`, качество данных не проверяется автоматически, регламент перезапуска не описан. Оформляем эту загрузку как SDD-изменение: фиксируем поведение в спеке, добавляем DQ-гарантии и регламент, чтобы дальнейшие правки шли через изменения, а не редактированием монолитного SQL.

## What Changes

- Новая capability `credit-agreements`: контракт загрузки `d_agr_cred` — три потока (ЭКС из `d_agr_cred_tmp`; ВДО из `v_agr_cred` + `d_agr_cred_core_uvdo`; core/COA из `d_coa_cred_core` + `v_coa`), гранулярность и ключ, правила `issue_dt` / `crncy_id` / цессии / флагов, гарантии уникальности.
- SQL загрузки фиксируется в `sql/d_agr_cred_load.sql` **без изменения логики** (brownfield-фиксация; рефакторинг — отдельные изменения).
- Регламент загрузки: полная перезагрузка раздела (результат не зависит от предыдущего содержимого), порядок шагов «подготовка `d_agr_cred_tmp` → `INSERT` → DQ», повторный запуск не дублирует строки.
- DQ-проверки после загрузки: уникальность `agr_cred_id`, `NOT NULL` ключевых атрибутов, сверка количества строк по потокам с источниками, контрольные примеры правил.
- Открытые вопросы фиксируются в дизайне: где выполняется очистка целевой таблицы; недетерминированный предикат `('now'::text)::date` в отборе `d_agr_cred_cust`.

## Capabilities

### New Capabilities

- `credit-agreements`: загрузка кредитных договоров (`d_agr_cred`) — источники и потоки, гранулярность/ключ, бизнес-правила выбора атрибутов (`issue_dt`, `crncy_id`, цессия, флаги), регламент загрузки и идемпотентность, DQ-гарантии.

### Modified Capabilities

Нет — требования других спек не затрагиваются (в проекте пока нет живых спек).

## Impact

- Новый файл `sql/d_agr_cred_load.sql` (текущий текст запроса как есть).
- Новая спека `openspec/specs/credit-agreements/spec.md`.
- Регламент и DQ-проверки добавляются к эксплуатации загрузки (инструмент сверок — по инфраструктуре команды).
- Потребители: витрины и отчёты, читающие `d_agr_cred`; структура таблицы и состав колонок не меняются.
